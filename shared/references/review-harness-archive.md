# 旧ハーネス記録の参照と移行

旧JSON台帳は新規利用を終了した。軽量版は[確認記録](review-harness-records.md)を使う。この文書は、過去の台帳・評価報告・証跡が必要なときだけ読む。

## 探す場所

合意したアーカイブは `~/.agents/state/archives/review-harness/2026-09-28/`。まずその `README.md` を読み、案件・runを絞って探索する。

| 旧保存先 | アーカイブ内の相対位置 |
| --- | --- |
| `~/.agents/state/review-harness/` | `review-harness/` |
| `~/.agents/state/review-harness-evaluations/` | `review-harness-evaluations/` |

移行前なら旧保存先を使う。移行済みかどうかと実際の移動日はREADMEの記録で確認し、移動予定を実績としない。記録中の旧絶対パスは上の対応で読み替える。過去の一時ファイルが見つからない場合は欠落と報告する。

旧契約2.1.0・書込み可能だった旧ツール1.1.0はAgentsのcommit `2766d4aa35acb1436f09f7a22415038ff75a663f`を参照できる。古い契約を現在の作業へ適用したり、旧書込みコマンドを復活させたりしない。旧runの失敗・期限超過を成功へ書き換えない。

## 読み取り専用の検証

現在の `review-harness-artifacts` 2.0.0は旧schema 1.0の`validate`だけを提供する。`append`と`check-target`は廃止した。`--state-root`は`review-harness/`の親を明示する。

```bash
uv run --isolated --frozen \
  --project ~/.agents/skills/review-remediation-harness \
  review-harness-artifacts validate \
  --state-root ~/.agents/state/archives/review-harness/2026-09-28 \
  --repository-id <repository_id> --run-id <run_id>
```

検証するのは、JSONの形式、連番の穴、過去recordへの参照、根拠fileのhash・長さ、未知fileの混入。成功時は保存先・件数・末尾情報を出す。エラー時は検証規則名など内容を含まない案内に絞り、payload・証跡の内容や不正な入力値を転載しない。

限界:

- 末尾の記録を整合的に削除した場合、内容とhashを整合的に書き換えた場合、保存先全体を古い状態へ戻した場合の完全な検出はできない。
- 対象コードの現在値、状態遷移、許可、予算、独立性、READYの正しさを判定しない。
- 成功は保存記録の限定した整合性だけを意味し、再開許可や改変がなかったことの証明ではない。
- 破損は原本を編集せず報告する。復旧が必要なら別の保存済み証拠と照合する。

## 移行するとき

1. 軽量版の手順と#61の記録を接続し、関連する検証・独立レビューを済ませる。移動対象へ書き込む進行中の作業がないことを確認する。
2. 私有領域に移動前の相対path・file数・内容hashの一覧を残す。symlinkや特殊fileがあれば、参照先を勝手に追跡してコピーしない。既存の移動先へ上書きしない。
3. 同じローカル領域内で旧台帳と評価ディレクトリを移動する。元のrecordや証跡のbytesを変更しない。切替失敗時に元の配置へ戻せるよう、対象と進行位置を残す。
4. 移動後に同じ一覧を取り、件数・相対path・内容の一致を確認する。一致しなければ完了にせず、原本を削除・書換えして帳尻を合わせない。
5. アーカイブREADMEへ経緯、実際の移動日、path対応、案件・runの探し方、参照する旧版、検証結果と限界を記載する。旧保存先には移動案内を残す。
6. READMEから代表的な台帳・評価報告・証跡へたどれることを確認し、軽量版の共通手順の参照先と実際の保存先を照合する。

移行はローカル運用作業であり、私有記録や一覧をGit管理・設定同期へ含めない。探索時も必要な範囲だけ読み、既知の秘密値を再探索しない。
